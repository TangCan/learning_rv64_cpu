# Bitloom capabilities — round 1

Accessed 2026-10-15. Primary sources: official TangCan/Bitloom docs, GitHub repo and docs.rs.

- **Identity:** `bitloom` is the CLI package (`cargo bitloom`); design crates depend on `bitloom-prelude`, and simulation is a separate `bitloom-sim` dev dependency. Latest published docs and GitHub release show 1.2.4 (released Oct 15). The repository README still said 1.2.2 as of Oct 14, a stale status line; pin and verify exact crate versions before any pilot. Source: https://docs.rs/crate/bitloom/1.2.4 (docs.rs/crates.io; published 2026-10-15; high; versions/package boundary) and https://github.com/TangCan/bitloom/releases (TangCan/GitHub; 2026-10-15; high; official release metadata), https://github.com/TangCan/bitloom (TangCan; page read 2026-10-15; medium; README status).
- **Relevant surfaces:** prelude documents const-width `Bits<N>`, `UInt<N>`, `SInt<N>`, state, modules, memories and CDC. `bitloom-sim` supplies cycle-tick on FrozenHir. Mainline build elaborates Rust design crates and emits Verilog; FIRRTL interop uses CIRCT/firtool. Source: https://docs.rs/bitloom-prelude/latest/bitloom_prelude/ (docs.rs; 1.2.4; 2026-10-15; high; API), https://docs.rs/bitloom-sim/latest/bitloom_sim/ (docs.rs; 1.2.4; 2026-10-15; high; API), https://github.com/TangCan/bitloom (TangCan; accessed 2026-10-15; high; flow).
- **Chisel interoperability:** documented `.fir` import path runs Chisel designs through their pinned Chisel/firtool flow, imports FIRRTL into FrozenHir, then emits/simulates; Bitloom explicitly says it does not parse Chisel Scala source. Thus this is a compatibility/debug path, not automatic Chisel-to-Rust rewriting. Source: https://github.com/TangCan/bitloom/blob/main/docs/fr46-chisel-import.md (TangCan; accessed 2026-10-15; high; tool integration).
- **Demonstrated CPU scale:** two documented tutorial cores are a trimmed single-cycle RV32I and a five-stage RV32 pipe with forwarding, load-use handling, branch flush, and optional minimal CSR/trap. The tutorials explicitly exclude cache, MMU, Linux, dynamic branch prediction, full privileged ISA, and arch-test. This is a useful starting proof, but not evidence that full RV64/CPU scale is validated. Source: https://github.com/TangCan/bitloom (TangCan; accessed 2026-10-15; high for stated scope, medium for absence claim).
- **Limits:** repo states Chisel output can be compilable and separately documents an idiomatic/maintainable path, so generated source quality needs evaluation. A documented memory-init helper has width ≤64, but this does not establish a complete CPU RAM/cache flow. Wider `Bits<N>`/vector operations and target-specific flows still need to be demonstrated in a pilot. Sources: https://github.com/TangCan/bitloom/blob/main/docs/fr28-chisel-compilable.md (TangCan; accessed 2026-10-15; high) and https://docs.rs/bitloom-builder/latest/bitloom_builder/ (docs.rs; 1.2.4; accessed 2026-10-15; high).

Searches: official repository/docs.rs for RISC-V, Chisel, FIRRTL, CPU examples, memory widths, and release notes. No documented RV64 CPU, RVA23 compliance, direct Veryl input, or parity claim found. Not found ≠ impossible.
