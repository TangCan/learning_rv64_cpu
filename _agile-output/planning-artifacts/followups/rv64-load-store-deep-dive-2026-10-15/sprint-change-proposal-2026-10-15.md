# Sprint Change Proposal：Bitloom RV64 试点

**日期：** 2026-10-15
**触发事项：** 调研 Bitloom 是否适合重写 Kunminghu 与 Heliodor RV64 CPU
**决策状态：** 已批准并完成独立试点规划基线

## 1. 问题摘要

Bitloom 提供 Rust RTL 设计、Verilog 输出和周期仿真能力，公开的 CPU 教程目前是 RV32 教学级核心。现有调研没有找到其支持 RV64/RVA23 大型 CPU 的独立证据。Kunminghu 和 Heliodor 包含乱序执行、向量、MMU、缓存、特权功能及系统级验证；Kunminghu 使用 Chisel/Scala，Heliodor 使用 Veryl，Bitloom 没有直接解析这两种源码的完整迁移路径。

因此，现有证据不支持承诺完整重写任一核心。更合适的问题是：是否用一个范围受限、可与两套上游实现对照的 Bitloom 试点，验证工具是否适合本项目的学习目标。

依据：[Bitloom 可行性调研](research/technical-bitloom-rv64-rewrite-feasibility-2026-10-15/research.md)。调研建议保持两套上游 CPU 为参考实现，并先验证代表性切片；未实施完整移植，也未验证生成 RTL 的综合/时序质量。

### 技术与验证影响

- 试点应固定 Bitloom CLI、设计 prelude 和仿真 crate 版本，并保留 Kunminghu/Heliodor 作为参照。
- 建议先实现 64 位整数状态/ALU、分支与 load/store，再加入一个 128 位向量操作和同步存储器，以覆盖研究中尚未得到端到端证据的宽度及存储行为。
- 交付证据应包括生成的 Verilog、逐周期或架构状态差分结果，以及可重复的构建/仿真记录。
- 试点通过后仍需评估综合、面积和时序；仿真相符不等同于全 ISA、RVA23 或整核等价。
- Chisel FIRRTL 导入只能作为可选实验，先检查 Kunminghu 实际输出是否落在 Bitloom 支持子集。没有发现 Veryl 直接导入路径。
- 当前不要求、不授权修改上游 RTL，也不授权开始完整 CPU 移植。

### UX、部署及其他影响

- 无 UI/UX、部署、基础设施或 CI/CD 影响；该项目的交付物是源码、仿真和学习文档。
- 如未来试点实际新增构建/仿真流程，应在该阶段规划中确定工具链和验证策略。

## 3. 路径评估与建议

| 选项 | 评估 |
|---|---|
| 直接调整当前 Epic | 不建议。当前 Epic 已完成，试点与原访存范围不同。 |
| 回滚已完成工作 | 不适用。调研没有推翻已完成的双核访存结果。 |
| 重审原 PRD/MVP | 不需要。原 RVA23 学习目标已完成；Bitloom 属于新增学习方向。 |
| 混合方案：另立有界试点阶段 | **推荐。** 保留全部结项基线，把试点作为新的可选阶段规划；先验证代表性切片，再决定是否扩展。 |

**范围分类：Moderate（中等）**：需要独立的阶段规划和 backlog，不需要重做既有阶段。若目标改为完整重写 Kunminghu/Heliodor，则属于 Major（重大）并需要新的架构与验证计划，本提案不建议该方向。

**工作量与周期：** 当前无法可靠估算。研究没有实现 Bitloom 原型，也没有测量适配、验证、综合或时序工作量；应在试点需求和环境检查后再估。

**主要风险：** Bitloom 对 RV64 及 128 位向量/存储语义的支持可能不完整；生成 RTL 的质量与验证生态未知；差分测试可能需要额外适配。以小切片、固定版本和明确停止门槛控制风险。

### 已批准提案 1：隔离为独立后续阶段

**用户决定：Approve。**

| 规划基线 | 当前内容 | 建议内容 |
|---|---|---|
| 已完成 RVA23 与访存阶段的 PRD、Epic、架构及 sprint | 记录原目标和完成情况 | 保持原样，不回滚、不重开、不改状态 |
| Bitloom 学习方向 | 尚无阶段需求或 backlog | 若用户批准继续，独立建立试点阶段规划；不把“重写两颗 CPU”设为验收目标 |

**建议的新阶段成功门槛（供后续规划确认）：**

1. 固定 Bitloom 工具版本及可复现的构建/仿真环境。
2. 选定一套可运行的参考测试，覆盖 RV64 整数、分支、load/store。
3. 实现一个 128 位向量操作与同步存储器案例，并生成 Verilog。
4. 保存 Bitloom 与参考实现的比较结果；差异必须可定位、解释，或明确标为未解决。
5. 记录综合/时序结果或明确说明工具链无法提供该证据。
6. 依据兼容性、验证成本和实现质量作出“停止、修正或扩大试点”的阶段决策。

这些门槛是新阶段规划的输入，尚未成为 PRD/Story 的正式验收标准。
