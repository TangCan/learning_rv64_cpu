# Bitloom RV64 学习试点

## 目标

为学习 RV64 CPU 的学习者提供一个可运行、可比较、可审查的 Bitloom 小型实现，用实证判断 Bitloom 是否适合承载本项目的部分 RV64 CPU 学习内容。Kunminghu 与 Heliodor 继续作为独立参考实现。

本试点不以重写 Kunminghu 或 Heliodor 为目标，也不声称生成核心符合完整 RVA23。

## 使用者与价值

本项目学习者希望在理解 Kunminghu（Chisel/Scala）和 Heliodor（Veryl）实现的同时，比较第三种 Rust RTL 描述方式。试点应让学习者能够从简单的 RV64 整数流水线逐步看到 load/store、受限向量操作、周期仿真与 Verilog 输出，并明确每项结果的证据边界。

## 范围

- 独立的教学级 Bitloom RV64 核心，不集成或替换上游 CPU。
- RV64I 的 64 位寄存器/ALU、顺序流水线、分支和受限的 load/store。
- 一个范围固定的 RVV 128 位向量操作：`vadd.vv`，SEW=32、LMUL=1、VL=4。
- 同步存储器模型、Bitloom 周期仿真和 Verilog 生成。
- 对相同输入比较架构可见结果；在两侧参考环境可用时分别记录 Kunminghu、Heliodor 结果。不可用的一侧标记为未验证，不以人工推断填补。
- 记录工具链、版本、命令、配置、日志、产物和已知限制。

## 功能需求

### F1：可复现工具链

- FR-1.1：记录 Rust、Bitloom CLI、设计 prelude、仿真 crate 及 HDL 工具的准确版本。
- FR-1.2：为试点固定 Bitloom 1.2.4 作为候选基线；第一条实现故事必须验证该版本能否完成最小设计编译、仿真和 Verilog 输出。失败时停止后续实现并形成变更建议，不静默升级或绕过限制。
- FR-1.3：提供可重复的本地命令和结果归档位置。

### F2：RV64 整数流水线

- FR-2.1：实现 64 位架构寄存器状态和 RV64I ALU 子集。
- FR-2.2：支持顺序取指、译码、执行、访存和写回，以及受测分支行为。
- FR-2.3：明确列出实现的指令子集；不支持的编码必须报告为未实现/非法指令，不得静默产生结果。

### F3：访存与参考比较

- FR-3.1：支持自然对齐的 `LD`、`SD`，使用确定性的同步存储器模型。
- FR-3.2：对固定输入比较退休 PC、寄存器写回和内存效果；分别记录 Kunminghu 与 Heliodor 可获得的参考结果。
- FR-3.3：区分仿真观察、静态源码依据与预期结果；未执行的参考测试不得标为通过。

### F4：受限向量案例

- FR-4.1：实现 128 位向量寄存器数据通路及 `vadd.vv` 的 SEW=32、LMUL=1、VL=4 案例。
- FR-4.2：测试四个 32 位 lane 的加法、lane 边界和向量结果写回；配置/向量状态超出该案例范围时明确拒绝或标记未支持。
- FR-4.3：将实现限定为该案例，不推断完整 RVV、V 扩展或 RVA23 支持。

### F5：输出与决策

- FR-5.1：从同一 Bitloom 设计生成可综合形式的 Verilog，并记录生成器版本和命令。
- FR-5.2：如环境提供综合工具，记录综合成功、资源和时序结果；否则记录工具缺口，不虚构 PPA 指标。
- FR-5.3：在阶段结束时根据兼容性、差分结果和输出质量作出停止、修正或扩大试点的决策。

## 非功能需求

- NFR-1：结果可由固定版本、固定输入和记录的命令重现。
- NFR-2：Bitloom 实现与两个上游仓库保持目录、构建和版本隔离。
- NFR-3：所有学习结论链接源码版本或运行证据；证据缺失明确标记。
- NFR-4：不以本试点结果宣称完整 RVA23 合规、全核等价或产品级性能。

## 验收与阶段门

试点成功交付需满足：

1. 固定工具链可重现地编译、周期仿真并生成 Verilog。
2. 定义的 RV64I 指令子集及受限 `LD`/`SD` 案例通过试点自检。
3. 受限 128 位 `vadd.vv` 案例通过 lane 级自检。
4. 与可用参考运行结果的架构差分有记录；每个不可比较点都说明原因。
5. 有综合/时序结果或明确的工具缺口说明。
6. 形成证据充分的继续/停止决策。

任何门槛未满足时可以结论为“试点未通过/工具不适合当前切片”；不得以扩展到完整 CPU 来掩盖失败。

## 不在范围内

- 重写、移植或修改 Kunminghu、Heliodor 的 RTL。
- 完整 RVA23、完整 RV64I、完整 RVV、特权架构或认证合规声明。
- 乱序执行、缓存一致性、MMU、分支预测、多核、Linux 启动。
- 自动转换 Chisel/Scala 或 Veryl 源码。
- 以仿真周期数与上游微架构做逐周期等价比较。
- 在试点决策门通过前开展完整核心实现或性能优化。

## 假设与待核实事项

- [待核实] Bitloom 1.2.4 支持本试点所需的 64 位、128 位向量数据、同步存储器及 Verilog 输出组合；公开文档没有证明该完整组合已经用于 RV64 核心。
- [待核实] Kunminghu 与 Heliodor 的本地固定快照均可为所选 RV64I/RVV 案例提供可重复的参考运行结果；先检查工具链和测试可行性。
- [待核实] 当前环境是否具备综合工具及可接受的目标工艺/约束；未指定目标前不设性能通过线。
