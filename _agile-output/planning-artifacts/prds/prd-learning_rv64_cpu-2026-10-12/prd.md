# PRD: RV64 CPU 双项目学习计划

*个人学习项目的需求基线；按项目需要裁剪产品文档结构。*

## 0. 文档目的

本 PRD 供学习者规划和推进 RV64 CPU 学习，也供后续架构与任务拆分流程使用。它定义学习结果、比较单元、学习路线和完成标准，不规定两颗处理器内部如何设计。上游源码和规范版本应能从每份学习记录中追溯。

## 1. 愿景

通过同一功能的双实现对照，建立从 RISC-V 架构行为到高性能处理器微架构和源码的连贯认识。主要参照为香山 Kunminghu V2 与 Heliodor；项目以学习和可验证的知识记录为成果，不以另造 CPU 为目的。

## 2. 学习者与目标

### 2.1 学习目标

- 能根据指令或功能的架构规范说明其可观察行为。
- 能在两边源码中定位实现入口，沿数据、控制和状态变化追踪到结果或提交。
- 能比较两种实现的微架构取舍，并用源码、设计文档、测试或小实验支持结论。
- [ASSUMPTION] 主要面向 Richard 个人学习；不要求预先掌握完整的 Chisel/Scala 或 Veryl 工具链，但会在学习中补足读代码所需知识。

### 2.2 用户旅程

单人技术学习项目不单列复杂用户旅程。一个学习单元从问题和规范开始，定位两边代码，追踪实现，查看验证证据，最后写下比较结论及尚未解决的问题。

## 3. 术语

- **学习单元**：围绕一个指令、扩展或微架构功能形成的一份可独立复习的对照记录。
- **对照记录**：包含规范行为、两边代码路径、验证证据、设计差异和学习者总结的 Markdown 文档。
- **来源快照**：学习记录所依据的上游仓库分支和具体 commit。
- **RVA23**：RISC-V 64 位应用处理器 profile，包含 `RVA23U64` 和 `RVA23S64`；本项目以官方规范确认要求，不将项目声明等同于正式认证。

## 4. 学习功能

### 4.1 上游来源与规范基线

项目使用香山 `kunminghu-v2` 分支和 Heliodor 上游仓库作为主要实现参照，并以 RISC-V 官方规范作为架构行为依据。

#### FR-1：记录来源快照

每份对照记录必须注明两边仓库链接、分支和所读 commit；更新源码版本时，学习者必须能识别记录所依据的版本。

#### FR-2：引用规范与验证证据

每份对照记录必须指向适用的 ISA/profile 规范和实现中的测试或验证证据；若找不到证据，必须明确标为未验证。

### 4.2 可复用的功能对照

每份对照记录说明问题和范围，给出架构行为，分别追踪香山与 Heliodor 的模块/文件及数据控制路径，比较设计取舍，并列出验证证据、结论和未解问题。

#### FR-3：从架构行为追踪到实现

学习者必须能从规范描述或指令行为追踪至两边实现的关键阶段和结果，不能只记录文件名或复制代码片段。

#### FR-4：总结差异及依据

每份对照记录必须至少说明一项有源码、设计文档或验证依据的实现差异；若实现方式相同，也需记录该结论的依据。

### 4.3 分阶段学习路线

路线按先修关系逐步深入，并允许根据学习反馈调整。MVP 先完成来源熟悉和 `ADD` 对照试点。对应阶段 2–4 的史诗 2–4 是候选范围，须通过 FR-5 的阶段门后才能启动获准的史诗。

#### FR-5：完成首轮对照并通过阶段门

MVP 先完成来源/环境基线、统一记录模板和整数 `ADD` 对照试点。试点复盘必须记录 `ready`、`adjust` 或 `defer`。`ready` 须确认记录方法、获准启动的史诗范围和学习节奏，并授权启动这些史诗；`adjust` 要先修订 PRD、史诗和路线，修订后仍须记录 `ready` 才能启动；`defer` 则暂停后续史诗，直到复盘另行决定。`BEQ`、`LD/SD` 是否加入以及后续主题的具体顺序均由该复盘决定。

#### FR-6：逐步覆盖核心主题

候选路线如下；每阶段以前一阶段的记录和检查通过为先修条件，阶段 2–4 对应的史诗须通过 FR-5 阶段门后才能启动。每阶段完成条件是：记录规范行为和两边源码路径、给出验证依据、回答该阶段的自检问题并保留答案。

| 阶段 | 主题 | 完成条件 |
| --- | --- | --- |
| 0. 来源与环境 | 仓库结构、版本快照、两种硬件描述语言及工具链入口 | 记录分支/commit；能在两边找到核心代码和现有测试入口；运行环境问题写入阻塞项 |
| 1. 指令路径 | `ADD` 起步，之后扩展到控制流和访存 | 完成试点对照记录；解释架构结果，定位两边译码/执行/写回路径，并引用验证证据 |
| 2. 乱序处理器 | 重命名、发射、执行、提交、分支恢复 | 追踪一条依赖指令和一次冲刷/恢复路径；区分两边对应结构 |
| 3. 内存与特权 | LSU、缓存、原子操作、异常、MMU 和特权级 | 追踪一次访存及一次异常或地址转换路径；说明相关测试或验证边界 |
| 4. RVA23 扩展 | 标量扩展、向量 V、虚拟化 H 及 profile 其余必选项 | 建立必选项映射，标出实现位置和证据；无法验证的项目明确标成未验证 |

阶段 1 的首个学习单元为 `ADD`。试点复盘确认的后续范围、顺序和节奏适用于获准启动的候选史诗。

#### FR-7：对照 RVA23 要求

路线必须把 `RVA23U64` 与 `RVA23S64` 的必选要求映射到实现对照或明确的范围决策；每项注明规范依据、实现位置和验证状态。不得仅凭 README 声明判定完整符合性，也不得把取得官方认证作为项目目标。

### 4.4 理解验证和知识沉淀

学习产物保存在本仓库中，使后续复习能够从结论回到上游代码、规范和测试。

#### FR-8：记录可复习的学习成果

每个已完成单元都必须有中文总结、来源快照、可复查的引用和未解问题。动手实验如有，需记录运行条件和观察结果。

#### FR-9：使用证据检查理解

每个阶段至少通过一次解释、源码定位或测试/仿真操作检查理解；未运行的测试不得记为通过。

## 5. 非目标

- 实现一颗新的完整 RV64 CPU、流片或追求性能指标。
- 复制或重新分发上游源码作为自己的学习材料；优先记录路径、行号、commit 和链接，并遵守各仓库许可证。
- 在未确认重点前穷举所有可选扩展、SoC 外设或工业实现细节。
- 宣称本学习仓库或所读实现已获得 RVA23 官方认证。

## 6. MVP 范围

### 6.1 范围内

- 建立两边来源与版本记录方式。
- 采用统一的对照记录模板。
- 完成 `ADD` 试点学习单元并检验对照记录模板。
- 为后续乱序执行、内存系统、向量、虚拟化和 RVA23 扩展形成候选路线，按 FR-5 阶段门启动获准范围。

### 6.2 MVP 范围外

- 对所有指令和所有可选扩展作完整覆盖；先验证对照方法有效，再按学习目标扩展。
- 修改上游核心或构建完整 SoC；如后续需要动手修改，作为独立实验再规划。
- 量化性能比较；本阶段重点是功能理解与架构取舍。

## 7. 成功指标

**主要指标**

- **SM-1**：完成一个 `ADD` 试点对照记录，包含来源快照、架构依据、两边实现路径和验证证据；按 FR-5 记录复盘结果并确认模板、后续范围和节奏。验证 FR-1 至 FR-5。
- **SM-2**：对每个阶段，学习者留存一份自检答案，至少解释架构可观察结果、指出两边关键源码路径、引用一项实现差异依据，并列出一个相关测试/边界案例。验证 FR-3、FR-4、FR-9。
- **SM-3**：完成 `RVA23U64` 与 `RVA23S64` 全部必选项的映射；对尚未深入学习的项目说明范围决定和原因。验证 FR-6 至 FR-8。

**反指标**

- 不以笔记数量或扩展覆盖数替代理解证据；若记录缺少代码、规范或测试依据，不计为完成。
