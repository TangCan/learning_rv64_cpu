# 技术结项调研对 PRD/史诗的差异提取

**输入：** [RV64 CPU 学习最终结项计划](../../research/technical-rv64-cpu-learning-completion-plan-for-re-2026-10-13/research.md)；当前 PRD 与 `epics.md`。本文件只提取需要 PRD/史诗决策的内容，不代替更新。

## PRD 层级：缺少或需澄清的要求/标准

- **定义整体结项标准。** 现有 FR-7、SM-3 要求完整映射 RVA23U64/RVA23S64 必选项；FR-9 要求每阶段至少一次理解检查。但没有明确“RV64 CPU 学习整体完成”还需对五项剩余主题（Zifencei、Sstc、Sscofpmf、Ssnpm、Ssstateen）形成双核深入学习记录、完成证据审计和复盘。宜区分“映射完成”与“学习单元及证据闭环完成”，并明确这仍不代表 CPU 符合性认证。
- **增加活动配置与可验证性要求。** PRD 要求源码路径和验证依据，但未明确源码中存在实现不等同于选定 Kunminghu 配置启用，也未规定须确认活动 CSR 路径、测试入口/依赖可用性，或对无法运行的项目记录具体阻塞。研究计划提出将这些作为 Epic 5 前置门，并将静态检查、测试材料检查、实际运行结果分开。
- **明确结项可接受的未验证/缺失状态。** 现有 FR-2/7/9 要求未验证项显式标记；研究计划进一步允许准确记录上游缺失或环境阻塞，但不允许靠改状态掩盖未知。PRD 可明确只要每项有证据边界、理由和结项影响判断，便可作为学习目标闭环，不要求补写上游 CPU 功能或声称标准符合。
- **规范版本/术语待判定。** 研究报告提示 RVA23 profile PDF 的 `PME` 与 Pointer Masking 规范/源码中的 `PMM` 命名有差异；现有 PRD/史诗未定义对照规则。应先核验适用版本及字段映射，再固定术语和需求条款，避免把 Supm/Ssnpm 与其他 pointer-masking 扩展混为一谈。
- **时间估算仅用于排期。** Epic 5 研究估算约 20–28 个 60–90 分钟时段（约 20–42 小时），不含工具链安装和超预期排障；现 PRD 的投入节奏与期限仍是开放假设，是否纳入正式成功指标需确认。

## Epic 5 范围与门槛影响

- 建议新增 **Epic 5：完成 RVA23S64 未调查主题的双核学习与证据闭环**，含五个单元：Zifencei/FENCE.I、Sstc、Sscofpmf、Ssnpm、Ssstateen；每单元比较两份固定快照、规范行为及测试/验证证据。Ssstateen 对 Heliodor 应允许以有边界的“未实现/未发现/待确认”结论闭环，不改上游核心。
- Epic 开始前核对 `sources.lock`；从配置追踪 Kunminghu 活动 CSR/NewCSR；确认 Heliodor 测试构建入口并有界检查其 Ssstateen 路径；盘点 ACT4/Sail、编译器、仿真工具和版本。门槛通过需需求到案例矩阵齐全、活动路径已确定或明确阻塞、测试计划区分现有与拟新增、工具依赖有记录。
- Epic 完成需五单元及双侧状态明确、运行案例有结果或具体阻塞、覆盖表/证据链接校验通过，并完成结项审计与 retrospective；当前 Story 5.6 所述 sprint validator 等验证工具仍需在实施规划时确认是否已有/可用。
- **门控关系待决策：** FR-5 及 Story 1.3 只授权史诗 2–4，Epic 5 不在既有 `ready` 门授权范围中。若沿用同一门控，需更新 FR-5/Story 1.3，规定 Epic 5 可被列入授权清单，或为 Epic 5 设单独启动门；不能从研究计划自动推定已获授权。

## 与现有 FR/史诗的重叠、冲突或边界

- **与 FR-7、SM-3、Epic 4 是深化关系，不是替代关系。** Epic 4 Story 4.7 已列 Zifencei、Sstc、Sscofpmf、pointer masking；Story 4.9 已列 Ssstateen；Story 4.10 要求完整映射。Epic 5 应承接这些映射，补足行为、活动实现路径和运行/验证证据，不重复重建全量 profile 清单，也不把五项深入学习误作 FR-7 的全部覆盖。
- **Story 4.7/4.9 的字段名需要修订或说明。** 现有 AC 写 `senvcfg.PME`、`henvcfg.PME`；研究计划发现字段命名差异，建议引用规范版本并记录 PME↔PMM 的映射，确认后再统一文本。此为待核规范问题，不据当前报告断言旧 AC 错误。
- **Epic 5 与 FR-6 阶段 4 的范围关系未写明。** FR-6 的 RVA23 扩展阶段含标量、V、H 及 profile 其余必选项，Epic 4 是“对照图谱”；建议明确 Epic 5 是 Epic 4 后续的深入单元/结项阶段，而非新增可选扩展范围。
- **FR-9 的“每阶段至少一次”可能弱于 Epic 5 验收。** Epic 5 对每个单元提出子案例证据，且整体 Done 要求五单元均闭环。应在 PRD 定义整体结项时的单元级证据要求，避免只满足阶段级一次检查便被视为整体完成。
- **不冲突的边界：** 研究计划不要求完整 CPU 开发、上游 RTL 修改或官方 RVA23 认证，与 PRD 的非目标一致；但用例中若新增学习者 harness/实验，应继续遵守现有实验隔离和记录约束。
