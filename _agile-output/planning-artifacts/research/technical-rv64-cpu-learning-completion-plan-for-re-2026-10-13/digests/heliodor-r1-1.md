## Extension-specific assessment and next evidence to collect

- **Zifencei:** README documents the ISA string and coherent I-cache/FENCE.I behavior. Find and inspect the actual fence.i arch test entry in `tb/test_arch_common.veryl`; verify default suite includes it, then run targeted and cross-hart code publication/self-modifying-code tests. Do not infer passing from ISA string alone.
- **Sstc:** `src/core/csr.veryl` has substantial implementation evidence; README also reports Sstc-in-VS directed tests in the default suite. Inspect the matching `tb/` test(s) and run boundaries: STCE off/on, compare below/equal/above time, delegated interrupt visibility, CSR access privilege, and guest timer enable/offset behavior.
- **Sscofpmf:** CSR evidence covers overflow aggregation and interrupt bits, but no specific test coverage appears in the README's named test list. Inspect counter/interrupt implementation and directed tests; exercise OF set/clear, counter enable masking, delegation, and privilege-mode filtering; compare expected CSR/interrupt state with architectural tests or Sail.
- **Ssnpm:** current inspected evidence is limited to configuration fields and a comment saying only PMM 33:32 is used. Determine the actual address transformation and fault behavior in fetch/load/store paths; test M/S/U and guest boundaries, disabled-vs-enabled modes, and tag bits. Search all source and test files before calling coverage absent.
- **Ssstateen:** not documented in the README and no `sstateen` identifier appears in inspected CSR source. Search the full source tree and generated CSR decode; if unsupported, record as an explicit remaining profile gap. If present elsewhere, add tests for implemented bits, WARL/read-zero behavior, and lower-privilege access gating.

## Limitations

All implementation conclusions above are static observations from pages retrieved in this run. The README's pass counts, ACT4 result, and Linux boot results are maintainer-reported results, not runs performed or independently verified here. The branch was not pinned to a commit, and failure to find an identifier in one file is not evidence of repository-wide absence.
