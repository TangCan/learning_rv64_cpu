topic: RV64 CPU 双项目学习规格
updated: 2026-10-12T14:04
---

- (decision) 采用同一架构功能对照 Kunminghu V2 与 Heliodor；学习成果是可复查记录，不是新 CPU。
- (capability) CAP-1 intent：学习者能从架构行为追踪到 Kunminghu 与 Heliodor 的实现，并比较设计。success：ADD 试点记录包含规范行为、双方关键路径、证据、差异或相同点依据、自检答案和未解问题。
- (capability) CAP-2 intent：学习者按先修路线逐步理解 RV64 从指令执行到乱序、内存/特权和 RVA23 扩展。success：每阶段有可复习的学习记录、答案和至少一项带证据的理解检查。
- (capability) CAP-3 intent：学习者能评估两个实现与官方 RVA23U64/RVA23S64 必选要求之间的映射。success：每个规范必选项对两边分别有状态、位置或范围决定、理由及证据，不存在空白项。
- (capability) CAP-4 intent：学习者能在需要时用隔离实验检验理解。success：任何学习者自建实验与上游源码分开，并记录源码快照、输入、步骤和观察结果；未运行的验证不报告为通过。
- (constraint) 首轮使用 Kunminghu 的 kunminghu-v2 分支（V2R2 文档/配置）与 Heliodor 上游；每个项目级基线固定完整 commit SHA，并通过 sources.lock 和稳定快照 ID 引用。
- (constraint) 以 RISC-V 官方 RVA23 Profile v1.0（Ratified）定义必选项；必选项、可选项、推荐和上游自述分开。项目证据不等于官方认证。
- (constraint) 每条比较结论要有两边证据 ID；运行证据记录命令、配置、输入、预期与观察结果。检查与实际运行分开，证据状态按架构约定词表记录。
- (constraint) 学习说明使用中文；ISA mnemonics、扩展名、符号和源码路径保留上游写法。学习记录使用统一结构、稳定 unit_id 和不可变版本文件。
- (constraint) 不在上游源码中直接编辑，不复制或重新分发上游源文件；学习者编写的 harness 与实验放在 experiments/<unit>/。
- (direction) MVP 是来源/环境基线、统一对照记录模板和 ADD 双核对照试点；试点后再选择后续具体指令与学习节奏。
- (note) 已批准的高层路线：阶段 0 来源和环境；阶段 1 指令路径；阶段 2 乱序处理器；阶段 3 内存与特权；阶段 4 RVA23 扩展。
- (note) 已批准的史诗与用户故事作为下游拆分基线，保留在 adopted companion epics.md；本规格不重复生成 stories.yaml。
- (non-goal) 不实现完整的新 RV64 CPU，不做流片或以性能指标为目标。
- (non-goal) 不穷举所有可选扩展、SoC 外设或工业实现细节；不把取得 RVA23 认证作为项目目标。
- (assumption) 按 PRD 当前假设，项目主要由 Richard 个人使用；需要的 Chisel/Scala 与 Veryl 阅读基础可以在学习过程中补足。
- (question) 学习节奏、每周投入时间和完成期限是什么？排期前确认。
- (question) 当前主机能否运行两个上游的仿真/测试工具链？阶段 0 盘点 OS、磁盘、内存和依赖后确认。
- (question) 上游仓库是否克隆到项目内 Git 忽略的 sources/，还是放在同级目录？克隆前依据仓库规模和磁盘确认。
- (question) 是否公开发布学习笔记？公开前检查许可证、引用和发布范围。
- (question) ADD 试点后是否需要 RTL 修改或其他动手实验？由试点复盘决定。
