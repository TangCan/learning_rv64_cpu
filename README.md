# RV64 CPU 双项目学习

本项目以香山昆明湖和 Heliodor 为参照，通过追踪同一条指令或同一项微架构功能，比较两种开源 RV64 处理器的实现。

## 参照项目

- **香山 Kunminghu V2**：优先跟踪稳定维护的 `kunminghu-v2` 分支。实现使用 Chisel，适合学习高性能乱序处理器及其工程验证体系。
  - 源码：https://github.com/OpenXiangShan/XiangShan/tree/kunminghu-v2
  - 文档：https://docs.xiangshan.cc/
- **Heliodor**：从头编写的 RVA23 RV64 乱序核，使用 Veryl，包含向量、虚拟化、缓存和 SMP 实现。
  - 源码：https://github.com/dalance/heliodor

两个项目的目录、语言和微架构并不完全相同。比较时以可观察的架构行为和数据流为主，不要求模块名称或内部结构一一对应。

## 学习顺序

按时间回顾探索过程和后续路线，见[RV64 CPU 学习日志](learning-journal/index.md)。经过整理的技术结论与证据仍以 [`notes/units/`](notes/units/index.md) 为准。

1. 从一条简单指令开始，追踪取指、译码、执行、提交/写回和测试。
2. 对比控制流指令、访存和异常处理。
3. 再学习乱序执行结构：重命名、发射队列、ROB、分支预测和恢复。
4. 最后进入 MMU、向量、虚拟化、缓存一致性和多核。

### 第一项对照：整数 `ADD`

两边分别找到 `ADD` 的指令定义/译码入口、执行单元、结果写回路径和对应测试。记录：

- 指令字段如何产生控制信息；
- 源操作数如何到达执行单元；
- 结果如何关联到目标寄存器并提交；
- 依赖、异常或冲刷会怎样影响这条指令；
- 哪个测试覆盖了加法及其边界情况。

完成 `ADD` 后，再用 `BEQ` 对照控制流及错误路径恢复。之后扩展至 `LD/SD`、原子指令和向量指令。

## RVA23 关注点

RVA23 是应用处理器 profile，不能仅凭“支持 RV64”判断完整兼容性。学习扩展时对照官方 [RVA23 Profile](https://docs.riscv.org/reference/rva23/index.html) 的必选扩展，并区分项目声明、架构测试结果和正式认证。
